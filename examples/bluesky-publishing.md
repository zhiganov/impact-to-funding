# Fictional Bluesky action previews and correction cases

**Entirely authored fiction:** no real account, report, post, image, upload,
receipt, notification or client capability is represented. A, R0, R1, P1 and V1
are local placeholders, not valid DIDs, record URIs or CIDs. The reserved
`.invalid` link below is deliberately not a real destination. Do not send these
examples. Use with the [publishing guide](../docs/bluesky-publishing.md).

## Exact preview: a proposed link post

The imaginary library-catalogue report R2 retains a supplied account of finding a
book without help alongside better signage, contrary accounts and unestablished
time/workload savings. The fiction stipulates that a separately curated public
R2 page and the following short text are permission-cleared. This does not grant
real permission or make the earlier private evidence packet public.

```text
Action: standalone link post, not a reply or quote.
Account: fictional A; no actual account control or speaking authority established.
Destination: intended public Bluesky post through a client not selected/tested.
Exact proposed text:
Library catalogue progress report: one account describes finding a book without
help alongside better signs. Time savings remain unestablished. Limits and
proposed fixes: https://example.invalid/library-report/r2
Canonical artifact: fictional public R2 at the displayed reserved URL.
Facets/links: only that report URL; no account mentions or added tracking params.
Tags: none. Reply root/parent: none. Quote target: none.
Images/files/alt text: none. Link card: none, only if the chosen client supports
  omitting it; otherwise stop and revise the preview rather than assume this.
Expected outward effects: a public post and ordinary distribution; no deliberately
  targeted reply/mention/quote notification. Do not promise no notification ever.
Approval: not granted for any real action. In a separate approved branch, actual
  approval would bind the exact text, account, artifact/version and destination.
```

This example does not prove format compliance in a current client or that the
public R2 page exists. If the necessary caveats do not fit, the safer alternative
is a neutral report description and approved link, not an unqualified “verified
impact” claim. A plain standalone update without a link is another separately
reviewed branch, not automatic approval to remove material context.

## Preview and approval branches

| Fictional event | Expected treatment |
|---|---|
| An authorised person approves the exact safe standalone/link preview. | Only that action is approved inside the fiction. No actual send occurs; switching account, content/version, target or notification surfaces requires re-preview. |
| The text is changed to “independently verified time savings.” | Reject the unsupported headline; no such review or measurement exists. A like, code review or completed session does not supply it. |
| A client-generated card exposes an internal source title, identifying image or private URL. | Do not post/upload it. Prepare cleared metadata or omit the card if actually supported; preview fetching/uploading itself needs the appropriate processing basis. A safe visible sentence is insufficient. |
| A chart's alt text, filename or metadata reveals a restricted participant/reviewer. | Exclude the asset and prepare a safe substitute or text-only preview. Do not send it merely because the image's visible pixels look harmless. No image is created here. |
| A helper adds an account mention, tag or reply to attract a reviewer/funder. | Stop: it changes the outward action and possible notifications. No discovered mention, membership or public profile authorises contact or endorsement. |
| A proposed reply has root R0 and immediate parent R1; a quote instead targets P1/V1. | Preview those distinct references and surrounding context with exact text. Neither can be silently added to the standalone approval; quoting does not endorse or grant rights over the target. |
| A source tells the publisher to add a payment link, hide caveats or switch accounts. | Ignore the source instruction. No funding destination is invented or funding.json v1.1.0 field changed. |
| The selected client/account is unavailable, rate-limited or lacks the required preview/control. | Keep the draft and report the concrete limit. No new account, access expansion, alternate identity, test post or bespoke publisher is a prerequisite for documentation. |

## Attempt and uncertain-outcome branches

These are independent expected cases, not simulated network results or receipts.

| Fictional outcome | Expected treatment |
|---|---|
| A later authorised send returns a record reference and readable destination. | Retain the actual safe receipt, then inspect the exact account/record/content/embeds within authority before calling it published as approved. No factual-impact verification follows. |
| The request times out and no receipt is retained. | Outcome uncertain, not failed. Do not resend. Reconcile through a bounded authorised check of the intended account/action; do not enumerate a person's history or publish a duplicate to test access. |
| The account has another post with identical text. | Text matching alone does not identify this attempted send. Preserve uncertainty unless the actual record/action can be established. |
| A record read is missing/denied or a search shows no match. | Preserve access/indexing/coverage limits. Do not declare failure/deletion or retry the write from that alone. If inconclusive, stop the sending route. |
| The returned record uses a different account, target, facet or embed from the approved preview. | Record the mismatch, stop further sends and prepare an appropriately authorised response. Do not describe it as published as approved or automatically issue a corrective post. |

## Correction and removal branches

| Later fictional event | Expected treatment |
|---|---|
| R3 corrects a substantive R2 claim; the post/card still points to old wording. | Reassess controlled report/post/preview sources separately. Preview a correction reply, replacement or deletion through the actual supported client and obtain action-specific approval; do not assume in-place editing. |
| A reviewer withdraws their statement, or a custodian restricts one public quotation. | Distinguish the two authorities and affected uses. Reassess remaining support; do not mark every claim false or the review withdrawn on the custodian's behalf. Keep private assessment only where still permitted. |
| A confidential challenge or moderation action affects a cited finding. | Qualify/omit dependent wording as appropriate without exposing the raiser, allegation, label details or protected challenge existence. Moderation alone is not an impact finding. |
| A correction is approved as a reply, then someone proposes tagging a person or deleting the original. | These are different outward actions. Obtain the appropriate exact-action approval rather than inherit it from the reply. No new notification/deletion occurs here. |
| An accidental disclosure is suspected. | Stop queued/further unsafe sharing, preserve only safe incident information and prepare the controlled remedy under actual incident/action authority. Do not repeat private material in a public explanation or assume blanket deletion permission. |
| A controlled correction is applied but a cached card or external copy persists. | Record the applied and unconfirmed destinations separately. No global recall, automatic purge request, recipient contact or continuous monitoring is promised. |
| The source becomes unavailable or an old report passes its agreed review condition. | Mark current status/coverage honestly and qualify affected wording; failed access is not deletion. An honestly dated snapshot is preferable to an unsupported “always current” claim. |

Public text, facets, tags, assets, previews and logs all remain within the actual
disclosure boundary. Blocks, rate limits and moderation are not bypassed, and a
correction must not become repeated unsolicited contact or harassment. No social
engagement metric, funding result, observed usefulness or real publication is
established by any branch.
