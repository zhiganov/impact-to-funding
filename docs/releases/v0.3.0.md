# v0.3.0 — managed installation and optional update notices

**Experimental source prerelease.** The release tag identifies the source
commit; it does not establish native activation or notice delivery for this exact
package. User-visible notices remain unverified.

## Changes since v0.2.0

- An optional managed CLI supports explicit installation, read-only checks,
  updates, adoption, rollback and recovery for native Claude Code, Codex CLI and
  OpenCode project/personal folders. It validates complete source snapshots and
  preserves local work rather than silently replacing unknown or changed files.
- Optional in-skill notices can tell the agent about an available release from
  the actual selected managed copy. Notices are off until explicitly enabled;
  the agent may show a non-blocking offer first. The helper does not install
  updates, and an agent may not relay its output to the person.
- Version/provenance metadata separates the skill version, helper version,
  selected release channel, full source commit and host-check evidence. Existing
  locked pins are not silently replaced by a newer release or moved tag.
- Git-for-Windows source preparation and long-path handling were corrected, and
  newer source trees declare LF text endings. Before changing an older CRLF clone,
  preserve local work, including ignored files, and review the destructive-step
  warning in the adoption guide. Windows checks
  on the earlier fix passed 41 of 44 tool tests; three symlink tests failed due to
  environment permissions. This is not a blanket Windows compatibility claim.

## Installation and updates

Use the complete package; do not copy only `SKILL.md`. Ordinary conversation does
not require Node.js, Git, an ItF account, a plugin or an MCP server. The optional
managed CLI and notices require Node.js 22+ and Git. Your host's sign-in, model
costs, file/tool permissions and privacy terms still apply.

Read `docs/managed-skill-updates.md` to preview an explicit install/update and
`docs/update-notices.md` for per-copy consent and opt-out. Older `v0.2.0` copies
do not contain the notice helper; updating the manager alone does not update them.
The manager's GitHub-addressed npm artifact is a bootstrap, not the skill bundle;
no npm registry publication or marketplace is required.

An enabled notice may request public GitHub release metadata. GitHub sees normal
network metadata, including the user's IP; the helper sends no prompt, project
file, evidence, local path or credential. Network permission and explicit consent
are both needed. Missing runtime/permission, offline access and unknown state do
not block conversation or establish that a copy is current.
