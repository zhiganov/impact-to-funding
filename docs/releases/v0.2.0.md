# v0.2.0 — contribution-centred skill and native CLI onboarding

**Experimental source prerelease**, not an install-tested package for every
documented host. The release tag identifies its exact source;
the host checks below remain tied to their earlier, explicitly named revisions.

## What changed since v0.1.0

- Start from the person's skills, situation and existing work, rather than requiring
  a theory of change or funding goal. Explore meaningful contribution, shared
  projects, capacity, learning and sustainable support without promising matches,
  income or impact certification.
- Add contribution portfolios, optional framework/systems guidance and a small
  source-linked library of cases and candidate patterns. Examples are authored
  fiction; patterns are hypotheses for adaptation, not proven universal solutions.
- Document native project-local installation and distinct invocation for Claude
  Code, Codex CLI and OpenCode, with complete-package preservation, safe updates,
  reversible removal and explicit verification limits. Add optional GitHub release
  subscriptions so users need not inspect every source commit.
- Add optional private evidence planning, reporting worksheets and funder-specific
  crosswalks, together with conduct-based responsible-assistance boundaries.
- Include optional local support-profile tools and a separate read-only library
  MCP. Neither is needed for conversation. A local tool or source contract does
  not establish a deployed consumer, funding service or automatically refreshed
  library connection.
- Record guild collaboration/curation assessments and fictional illustrations.
  These are documentation and design, not deployed Groups integration, operator
  authority, financial allocation or a membership registry.

## Installation and verification

Use the complete package and your host's native folder/invocation; do not copy
only `SKILL.md`. ItF itself needs no account, Node.js, MCP or plugin for ordinary
conversation. Your host's sign-in, model costs and privacy terms still apply.

## How to update

Updates are optional. Read the release notes and licensing changes first, record
your installed SHA and preserve local changes and private material. Resolve the
chosen release tag to its full commit and follow the package's `docs/install.md`
update steps. Existing host-tested pins remain historical options; moving to this
source prerelease does not make the newer package install-tested.

On GitHub, choose **Watch → Custom → Releases** and enable the watching notification
delivery you want, or visit the releases page without subscribing. Notifications
do not update the installed files; there is no background update check.

## Still not provided

No matching network, introductions, participant recruitment, funding, impact
certification, live Groups operations, automatic financial allocation, marketplace
distribution or desktop/cloud/Cowork support is delivered by this prerelease.
Private transcripts and verification traces are not bundled. Read `PRIVACY.md`
before supplying real material; local installation does not imply local-only
model processing.
