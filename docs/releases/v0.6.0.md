# v0.6.0: an optional Claude Code plugin

**Experimental source prerelease.** The release tag identifies its source commit.
This release covers changes since v0.5.0 (`a30f627`).

## What changed in the skill

- **Guidance the agent reads now lives inside the skill.** Seven guides moved from
  `docs/` into `references/`: responsible assistance, evidence and reporting, signal
  discovery, signal enrichment, Bluesky publishing, support-profile tools and the
  support-profile contract. The old `docs/` paths keep a short note pointing to the
  new place. Links to tool guides now go to each tool's own README, and rules the
  skill needed from design notes are stated in the linking file. The skill's own
  files no longer link into `docs/`, and a package test keeps it that way (#126).
  The guidance itself is unchanged apart from links.

## New or changed local tools

- **Claude Code plugin** (`tools/claude-plugin`): builds one `itf` plugin from a
  release commit. It holds the skill, the files the skill links to, the reference
  library MCP and its runtime, the licence texts and a provenance file with the hash
  of every file. Links from copied reference files to files the plugin leaves out
  point to GitHub at the release commit. The skill appears as
  `/itf:impact-to-funding` (#129).
- **Library runtime build** (`tools/library-runtime`): turns one release commit into
  a folder that runs the reference library MCP with Node alone, with no Git history,
  no `npm install` and no network. It holds the server, its three production
  packages with their licences, a prepared snapshot and a provenance file. The
  plugin uses it (#127).
- **Windows:** the shared install step now starts npm without a shell, so the
  runtime build runs on Windows (#128). `itf setup` still supports macOS and Linux
  only.

## Docs

The [installation guide](../install.md) adds the plugin as an optional route next to
the skill folder, which stays the default. The release-notes skill now covers
building, zipping and listing the plugin after a tag.

## Use and updates

Continue to invoke the existing `impact-to-funding` skill. Use the managed CLI's
prerelease channel to preview v0.6.0, or select its full source commit. Existing
installations don't update themselves.

From this release, Claude Code users can instead install the plugin:

```sh
claude plugin marketplace add https://github.com/zhiganov/impact-to-funding.git
claude plugin install itf@impact-to-funding
```

The plugin needs Claude Code 2.1.281 or later, and Node.js 22 or later for the
library MCP. It changes only when you run `claude plugin update itf`. If the plugin
is enabled, `itf setup --harness claude` stops rather than registering a second
library server. See the [installation guide](../install.md) and the
[managed update guide](../managed-skill-updates.md).

## Evidence and limits

- The plugin was built from `9a7f104`, passed `claude plugin validate`, and was
  checked in an isolated Claude Code 2.1.296: install, the namespaced skill, the
  library server connecting with a three-tool round trip, the setup guard,
  a missing Node failing visibly, and disable and uninstall
  ([check record](../checks/claude-plugin-2026-11-19.md)). The plugin attached to
  this release is built from the release commit itself, and its checks are recorded
  in the GitHub release text.
- The runtime build passed its own source-bound check and matched byte for byte
  across two builds, on macOS (Node 26.13.1) and on Windows 11 (Node 24.13.0).
- The guidance move was checked by comparing each moved file with its original:
  only link targets changed. No model run was needed.
- Each tool's tests passed when it merged.
- No model conversation was run with the plugin, so its routing and usefulness are
  unchecked. Earlier host checks cover only their recorded source revisions.
