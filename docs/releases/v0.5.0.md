# v0.5.0: shorter core, new playbooks and local tools

**Experimental source prerelease.** The release tag identifies its source commit.
This release covers changes since v0.4.0 (`abba020`).

## What changed in the skill

- **Shorter core.** `SKILL.md` keeps its purpose, boundaries, update notice, start,
  routing and finish, and states each always-on rule once. Task guidance moved to
  the references the routing already pointed to, including a new
  `references/learning.md`. The core went from about 24,400 to about 13,800
  characters (#83, #84).
- **Funder application rules.** Before drafting for a named funder, the agent reads
  the funder's form and guidance for rules that shape the draft: questions, limits,
  attachments, eligibility, deadlines and any stated AI policy (#72).
- **Funder research.** The agent prefers each funder's own page to aggregator
  listings and labels which is which. It records each status with the date checked,
  lists checks still needed, and offers a date-stamped private save (#81).
- **Mentors.** When someone wants a mentor, the agent helps them think of people and
  communities they already know and prepare a short request. ItF keeps no mentor
  pool (#87).
- **Taking stock.** The agent can offer six optional check-in questions and a bounded
  request for peer feedback (#88).
- **New playbooks:**
  - GitHub sponsorship: drafting profiles, tiers, funding links and updates (#92).
  - Contributing skills to existing organisations, for builders without a project
    of their own (#95).
- **Optional offers in the support-brief playbook:** a readability check on drafts,
  a Pangram check where the person has it connected (#76), and an impact badge once
  they have an approved public report (#79).
- **Reference library:** a third lens, L003 on the EAT-Lancet Planetary Health Diet
  (#90). The library still has no food-system case.

## New local tools

All run locally on Node 22 or later. None is needed for conversation.

- **Readability check** (`tools/readability`): reading grade, long sentences,
  passive voice and adverbs for briefs, reports and profiles (#74, #75).
- **Impact badge** (`tools/impact-badge`): a shields.io badge, light and dark SVG
  cards, and an HTML card for websites, from a support profile and a small input
  file. It never shows a score or "verified" (#77, #80).
- **Portable records** (`tools/portable-records`): a JSON and Markdown round trip
  for claim, report and review records (#82).
- **GitHub sponsorship tools** (`tools/github-sponsorship`): a read-only
  funding-readiness review, a read-only Sponsors account overview, and offline
  reporting from an exported transactions CSV. They don't change accounts or
  sources.
- **Library MCP:** now maps L003 (#91).
- **Managed update tool:** a `--commit` pin that matches a published release now
  records that release's version, and so does a pin-only update (#85). The
  [managed update guide](../managed-skill-updates.md) explains how to read releases
  behind a proxy.

## Docs

The README and main guides were rewritten in plain language (#69). New guides cover
optional writing tools, the impact badge contract, mentor pool scoping and the
builder check-in assessment.

## Use and updates

Continue to invoke the existing `impact-to-funding` skill. Use the managed CLI's
prerelease channel to preview v0.5.0, or select its full source commit. Existing
installations don't update themselves. See the [installation guide](../install.md)
and the [managed update guide](../managed-skill-updates.md).

## Evidence and limits

- Behavioural checks in Claude Code, with fictional prompts, compared the skill
  before and after the core changes (#83, #84). They found no regression on those
  prompts. They don't show general model reliability.
- Each tool's tests passed when it merged. Each tool's guide records its checks.
- The impact badge was checked on shields.io, GitHub's renderer, Chromium in light
  and dark mode, and a fictional Astro build.
- The new playbooks' host routing hasn't been checked in a host.
- Earlier host checks cover only their recorded source revisions.
