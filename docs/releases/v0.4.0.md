# v0.4.0 — optional support-brief playbook

**Experimental source prerelease.** The release tag identifies its source commit.
The new playbook's host routing and model behaviour are unverified.

## What changed

The existing person-first skill now links to an optional support-brief playbook.
It helps organise a request for financial or non-financial support without making
fundraising the purpose of every conversation.

When relevant, the playbook covers what support would enable, known costs, the
recipient, existing support, evidence permissions, an authorised funder shortlist
and a provisional or final brief. A `funding.json` candidate remains optional for
appropriate OSS financial cases. General support can use the separate support-profile
guidance if requested.

The funding reference now treats a named or completed theory of change as optional.
A clear rationale can help when it fits the task. A brief can remain provisional
while the recipient, budget, evidence or funder is unknown.

## Use and updates

Continue to invoke the existing `impact-to-funding` skill in your chosen host.
You can request a brief in ordinary language or include `support-brief` as task
text. It is not a separately registered command. The skill directs the agent to
read the playbook from the selected complete package; copying only `SKILL.md`
leaves it behind.

Use the managed CLI's prerelease channel to preview v0.4.0, or select its full
source commit deliberately. Existing installations do not update themselves.
The [installation guide](../install.md) and [managed update guide](../managed-skill-updates.md)
explain the options. Conversation needs no Node.js or funding account.

and link checks. They check source structure and wording, not model behaviour.
The usage guide contains an authored fictional illustration; it is not a model
response. The [earlier field note](https://github.com/zhiganov/impact-to-funding/issues/57#issuecomment-6753943272)
is one reported experience, not general proof of effectiveness.

Previous limited Claude Code and Codex CLI checks cover source `4566892`.
Historical OpenCode v2.2.5 checks cover `fbb8993`. No host or model run was made
for v0.4.0. The earlier opt-in update notice also remains unverified as a
user-visible host experience.

The playbook uses the skill's shared privacy, evidence and responsible-assistance
boundaries. It keeps funder research within the authorised task and preserves the
person's authority over outreach, applications, publication and money. A brief
does not establish eligibility, independent review, funding or impact.
