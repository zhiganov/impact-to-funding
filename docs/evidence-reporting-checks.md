# Manual evidence/crosswalk source checks

**Date:** 2026-11-09. **Scope:** manual source support for
[#48](https://github.com/zhiganov/impact-to-funding/issues/48), following the
[published design](evidence-reporting-design.md). These are source/template and
authored-fixture checks, not observed model behaviour or real funder submissions.

## Source path reviewed

- One conditional routing rule in [SKILL.md](../SKILL.md) selects the existing
  guidance and [optional private worksheet](../assets/evidence-crosswalk.md) only
  when collection planning or audience-specific drafting helps the request.
- Existing assessment and report templates link to the worksheet; the claim
  reference remains the single assessment convention. No new executable schema,
  parser, database, collector or provider contract is introduced.
- Usage/privacy guidance separates the actual host/provider processing basis,
  evidence fit, exact destination permission and actual presentation checks.
  Ordinary exploration and prospective work remain possible without these records.

## Literal fixture and package checks

The two original destination-view quotation blocks were compared to the released
source and are **unchanged**. A local whitespace-delimited word count found
**48 words** for the 80-word Access Seed field and **76 words** for the 300-word
Maintenance Circle field. Literal checks retained 9/12, three failures, absent
comparison, unconfirmed responsibility/timing and the partner-review limitation.
The two blocks contain no internal E2/E3/C1 references or source URLs. Those are
narrow fictional-text checks, not a general disclosure detector or actual form test.

Root package checks use `node --test tests/package.test.mjs`; they validate metadata,
licence scope, local links and text integrity. **5/5 passed**, and `git diff --check`
passed. They cannot establish reliable routing or privacy completeness.

## Unverified and unchanged boundaries

No fresh model response, native installation, real collection, participant consent,
actual form/schema validation, provider interoperability, application acceptance,
eligibility, award, human usefulness or impact was tested. The installed skill's
existing evidence stays tied to its exact previously checked revision; this source
change does not update it.

The optional funding consumer remains separate work under #35. No private provider
contract details, source packet, restricted identity/locator or actual application
is bundled. The root financial manifest, public library records, library MCP and
support-profile runtime are outside this manual change. Completing a worksheet
authorises no evidence upload, submission, publication, outreach or payment.
